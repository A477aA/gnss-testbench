# Дефекты, найденные при разработке стенда

Все три дефекта — настоящие: тесты поймали их в процессе написания проекта.
Каждый закрыт регрессионным тестом.

---

## BUG-001. Дата RMC с годом 94 разбирается как 2094 вместо 1994

| Поле | Значение |
|---|---|
| Компонент | `nmea/parser.py`, `parse_date` |
| Серьёзность | Major — неверная дата в навигационных данных |
| Приоритет | High |
| Обнаружен | Тест на эталонной строке NMEA 0183 |
| Статус | Исправлен, регрессионный тест `test_date[230394-...]` |

**Шаги воспроизведения**
1. `parse("$GPRMC,123519,A,4807.038,N,01131.000,E,022.4,084.4,230394,003.1,W*6A")`
2. Посмотреть поле `date`.

**Ожидаемый результат:** `1994-03-23`.
**Фактический результат:** `2094-03-23`.

**Причина.** В RMC год двузначный, а парсер всегда прибавлял 2000.

**Исправление.** Опорный год 80: значения yy ≥ 80 — это 19yy, остальные — 20yy. Отсчёт GPS-времени
начинается в 1980 году, так же поступают gpsd и pynmea2. Добавлены граничные тесты на годы 79 и 80.

## BUG-002. GSA с типом решения «0» принимается как «нет решения» вместо ошибки

| Поле | Значение |
|---|---|
| Компонент | `nmea/parser.py`, `parse_gsa` |
| Серьёзность | Minor — некорректные данные молча принимаются |
| Приоритет | Medium |
| Обнаружен | Негативный тест `test_gsa_invalid_modes[A-0]` |
| Статус | Исправлен |

**Шаги воспроизведения**
1. `parse(build_sentence("GPGSA,A,0,04,,,,,,,,,,,,2.5,1.3,2.1"))`

**Ожидаемый результат:** `FieldError` — допустимые значения 1, 2, 3.
**Фактический результат:** `fix_mode = NO_FIX` — недопустимое значение молча заменено.

**Причина.** Выражение `_int(value) or 1` превращало `0` в `1`: в Python ноль ложен, как и `None`.
Классическая ошибка, когда «пустое поле» и «ноль» обрабатываются одинаково.

**Исправление.** Явная проверка `is None`.

## BUG-003. Начало потока теряется при подключении к порту

| Поле | Значение |
|---|---|
| Компонент | Тестовое окружение: `sim/pty_port.py` + `capture.py` |
| Серьёзность | Major для стенда — сквозные тесты падали |
| Обнаружен | Интеграционные тесты: принятые байты не совпали с отправленными |
| Статус | Исправлен, поведение зафиксировано тестом `test_data_sent_before_port_opened_is_lost` |

**Шаги воспроизведения**
1. Запустить вещание эмулятора в pty.
2. Открыть порт через `serial.Serial(...)`.
3. Сравнить принятые байты с отправленными.

**Ожидаемый результат:** совпадают побайтно.
**Фактический результат:** первая эпоха (или её часть) отсутствует.

**Причина.** `pyserial` при открытии порта вызывает `tcflush` и сбрасывает входной буфер.
Всё, что пришло до открытия, теряется. С реальным приёмником происходит то же самое.

**Исправление.** Эмулятор начинает вещание по сигналу `on_open` после открытия порта.
Отдельный тест проверяет, что при подключении «на лету» декодер переживает обрезанную первую строку.

**Вывод для работы с реальным железом:** при подключении к уже работающему приёмнику
первая строка лога может быть неполной. Это норма, а не дефект прошивки.

## Наблюдение (не дефект). Высокоточные GGA длиннее 82 символов

Строки GGA с координатами вида `5541.6880000` (7 знаков минут, около 0.2 мм) не укладываются в
ограничение NMEA 0183 в 82 символа. Многие RTK-приёмники это ограничение превышают. Декодер такие
строки принимает, но считает их в `non_standard_length`, и они попадают в отчёт. Если по
требованиям проекта приёмник должен строго соответствовать стандарту, эту метрику можно сделать
критерием приёмки.
